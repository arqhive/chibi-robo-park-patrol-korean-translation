# 검수용 치트 (melonDS, 일본판 AJBJ)

검수를 빨리 하려고 만든 액션 리플레이 코드다. 롬은 고치지 않는다. melonDS의 치트 관리에 넣어 켜고 끈다.

## 찾은 방법 (2026-11-06)

- 세이브 스테이트 3개(치비로보 와츠 약 99 → 97 → 94)의 메인 RAM(파일 36바이트부터가 0x02000000)을 비교했다.
- 와츠는 float이다. 세 값이 한 구조체에 붙어 있다.
  - 구조체 주소는 전역 변수 `0x021E64A8`에 들어 있다. 이 주소는 코드의 리터럴 풀에서 직접 참조하므로 고정 주소다. 세 스테이트 모두 값은 `0x02383934`였다.
  - `+0x3A0` 치비로보 현재 와츠
  - `+0x3A4` 하우스 와츠 (세 스테이트 모두 89)
  - `+0x3A8` 치비로보 최대 와츠 (100, MAX와츠를 사면 늘어남)

## 코드

### 치비로보 와츠 무한 (항상 최대값으로 채움)

```
621E64A8 00000000
B21E64A8 00000000
D9000000 000003A8
D6000000 000003A0
D2000000 00000000
```

최대 와츠 값을 읽어 현재 와츠에 쓴다. MAX와츠를 사서 최대가 늘어도 그대로 따라간다.

### 하우스 와츠 99999

```
621E64A8 00000000
B21E64A8 00000000
000003A4 47C34F80
D2000000 00000000
```

`47C34F80`은 float 99999.0이다(11/06 9999에서 올림). 다른 값이 필요하면 float 16진수로 바꾼다.

### 디스크 돌리기 점수 100점

```
52386CE8 4718BC08
52386CC8 0211EABC
02386CE0 00000064
D2000000 00000000
```

- 세이브 스테이트 3개(점수 40·34·51)를 비교해서 찾았다. 점수는 32비트 정수이고 주소는 `0x02386CE0`(힙)이다.
- 같은 객체의 고정 값 두 개(`+8`의 `0x4718BC08`, `-0x18`의 `0x0211EABC`)가 맞을 때만 100을 쓴다. 다른 장면이나 다른 메모리 배치에서는 아무것도 쓰지 않는다.
- 힙 주소라서 게임을 새로 켰을 때 위치가 달라지면 효과가 없을 수 있다. 그때는 스테이트를 다시 받아 주소를 찾는다.

### 물 한 번에 꽃 피우기 (시험 중, 2026-11-06)

```
520D63E0 00009001
020D63E0 00064000
D2000000 00000000
520D63E4 00001CCD
020D63E4 00064000
D2000000 00000000
```

- 세이브 스테이트 1~3(물 0회·조금·더)과 5·6(피기 직전·핀 직후)을 비교했다. 필드 물체 모델(함수 표 `0x02137BA0`, 0xA0바이트)의 `+0x50`에 물 누적값(fx32)이 쌓이고, `+0x0C` 애니메이션 번호가 0x34 → 0x36 → 0x39(핀 꽃)로 바뀐다.
- 물을 맞는 동안 누적값을 더하는 코드는 `0x020D6382`이다. 더하는 양은 리터럴 `0x020D63E0`(9.0, 조건 있을 때)과 `0x020D63E4`(1.8, 보통)이다. 이 리터럴은 이 함수에서만 쓴다.
- 두 값을 100.0(`0x00064000`)으로 바꾼다. 원래 값일 때만 쓰니 다른 데이터를 덮지 않는다. 누적값은 코드에서 상한으로 잘리니 이것만으로 피는지는 게임에서 확인해야 한다.

## 설치 위치

- 2026-11-06 바탕화면 `Chibi-robo.mch`(롬 `Chibi-robo.nds` 옆, melonDS 기본 위치)에 두 코드를 켠 상태로 넣었다. melonDS 설정 `EnableCheats = true`.

## 주의

- 구조체가 아직 없는 화면(타이틀 등)에서는 첫 줄의 조건(포인터가 0이 아닐 때만)으로 아무것도 쓰지 않는다.
- 2026-11-06 사용자가 melonDS에서 세 코드 모두 동작 확인(「모든 치트가 적중했다」). 디스크 점수 100점으로 꽃도 핀다.
